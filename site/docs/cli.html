CLI reference

Every command below is generated from a real bin/pb help <command> run against this repo's build — terminal blocks are verbatim output, not hand-written. pb help <command> and pb <command> --help/-h are equivalent for every command; running pb with no arguments, or pb help alone, prints the full usage summary below.

Usage summary

$ pb help
pb — prove agent changes work, end-to-end, on any setup

Usage:
  pb evidence new     --claim C --phase P [--root DIR] [--ticket T] [--kind K] [--pairs-with RUNID] [--surface k=v ...]
  pb evidence run     --bundle DIR --name NAME [--shell] [--] CMD [ARGS...]
  pb evidence add     --bundle DIR [--type TYPE] [--name NAME] [--meta k=v ...] SRC_PATH
  pb evidence link    --bundle DIR EXECUTION_ID URL
  pb evidence assert  --bundle DIR EXPR
  pb evidence seal    --bundle DIR
  pb evidence verdict --bundle DIR [--note NOTE] pass|fail|inconclusive
  pb evidence validate BUNDLE_DIR
  pb evidence show     BUNDLE_DIR
  pb init   [--out FILE|-] [--force] [DIR]
  pb lint   [--manifest ready.yaml]
  pb up     [--substrate local|compose|k8s-attach] [--manifest ready.yaml]
  pb ready  [--substrate local|compose|k8s-attach] [--manifest ready.yaml]
  pb seed   [--substrate local|compose|k8s-attach] [--manifest ready.yaml]
  pb down   [--substrate local|compose|k8s-attach] [--manifest ready.yaml]
  pb verify [--ticket T] [--claim C] [--evidence-root DIR] [--only a,b]
            [--substrate local|compose|k8s-attach] [--manifest ready.yaml]
            [--pairs-with RUNID] [--kind before|after]
  pb explore [--manifest ready.yaml] [--out DIR] [--runtime claude-code] [--max-turns N]
             (experimental: requires PB_EXPERIMENTAL=1; proposes checks only, never a verdict)
  pb report BUNDLE_DIR
  pb hub    [--root DIR] [--out FILE]
  pb version

Exit codes: "pb evidence run" exits with the wrapped command's real exit
code; "pb evidence assert" exits 1 when the predicate fails, 2 on
evaluation error; "pb lint" exits 1 with the named validation error; "pb
explore" exits 2 when PB_EXPERIMENTAL is not set to "1", 3 when the round
did not run (not-run), 4 when it ran but produced no proposal
(inconclusive); every other command exits nonzero on failure.

Run "pb help <command>" for details and an example of any command.

version

pb version, pb --version, and pb -v are all the same command.

$ pb version
pb version 0.1.0-dev
$ pb --version
pb version 0.1.0-dev
$ pb -v
pb version 0.1.0-dev

init

Detects the project's run/ready/seed shape and writes a starter ready.yaml manifest.

$ pb help init
Detects the project's run/ready/seed shape and writes a starter ready.yaml manifest.

Flags:
  -force
    	overwrite an existing output file
  -out string
    	output path for the generated manifest ('-' for stdout) (default "ready.yaml")

Example:
  pb init .

When it can't derive a real start command, pb init still writes a runnable-looking file with the literal placeholder echo TODO: set your start command in run.local.start — pb lint rejects that placeholder once you've replaced it.

lint

Parses and validates a ready.yaml manifest without bringing anything up.

$ pb help lint
Parses and validates a ready.yaml manifest without bringing anything up.

Flags:
  -manifest string
    	path to ready.yaml (default "ready.yaml")

Example:
  pb lint --manifest ready.yaml

Prints ok and exits 0 when the manifest is valid; exits 1 with the specific validation error (see the Validation section of the ready.yaml reference) otherwise.

up / ready / seed / down

The four substrate-lifecycle commands share the same two flags. Each brings up, probes, seeds, or tears down the service on the chosen substrate.

$ pb help up
Brings the service up on the chosen substrate (local process, docker compose, or an attached k8s workload).

Flags:
  -manifest string
    	path to ready.yaml (default "ready.yaml")
  -substrate string
    	local|compose|k8s-attach (default "local")

Example:
  pb up --manifest ready.yaml
$ pb help ready
Waits for and checks the service's readiness probe (http, tcp, or exec) on the chosen substrate.

Flags:
  -manifest string
    	path to ready.yaml (default "ready.yaml")
  -substrate string
    	local|compose|k8s-attach (default "local")

Example:
  pb ready --manifest ready.yaml
$ pb help seed
Runs the manifest's declared seed steps against the running service.

Flags:
  -manifest string
    	path to ready.yaml (default "ready.yaml")
  -substrate string
    	local|compose|k8s-attach (default "local")

Example:
  pb seed --manifest ready.yaml
$ pb help down
Tears the service down on the chosen substrate.

Flags:
  -manifest string
    	path to ready.yaml (default "ready.yaml")
  -substrate string
    	local|compose|k8s-attach (default "local")

Example:
  pb down --manifest ready.yaml

Each exits nonzero on failure — e.g. up against k8s-attach exits nonzero if kubectl is missing, no k8s locator is declared, or a port-forward never comes up; down is idempotent and treats already-torn-down state as success.

verify

Brings up the substrate, runs the manifest's checks, and produces an evidence bundle with a tri-state verdict (pass/fail/inconclusive).

$ pb help verify
Brings up the substrate, runs the manifest's checks, and produces an evidence bundle with a tri-state verdict (pass/fail/inconclusive).

Flags:
  -claim string
    	claim under verification
  -evidence-root string
    	root directory for evidence bundles (default "evidence")
  -kind string
    	before|after (this bundle's role in a paired run)
  -manifest string
    	path to ready.yaml (default "ready.yaml")
  -only string
    	comma-separated check names to run (default: all)
  -pairs-with string
    	runId of the paired bundle (before/after pairing)
  -substrate string
    	local|compose|k8s-attach (default "local")
  -ticket string
    	ticket key recorded in the bundle

Example:
  pb verify --manifest ready.yaml --claim "orders endpoint returns totals" --ticket ENG-123

Exit-code semantics come straight from the proof ladder, not a generic pass/fail: pb verify exits 0 only when the bundle's final verdict is pass; a verdict of fail or inconclusive — including an honest not-run gating from an unmet checks[].requires or an unattached substrate — exits 1. The rung actually reached is printed on its own proof: line rather than folded into the exit code, so a caller can tell "ran, but only reached L3" from "never ran" by reading the bundle, not by guessing from the shell status alone.

explore experimental

Runs one agent-driven exploration round via the embedded headless-agent runtime — see Headless agents for the full adapter contract and failure taxonomy.

$ PB_EXPERIMENTAL=1 pb help explore
Experimental: runs one agent-driven exploration round that proposes checks for ready.yaml. Never produces a verdict and never edits the manifest. Requires PB_EXPERIMENTAL=1.

Flags:
  -manifest string
    	path to ready.yaml (default "ready.yaml")
  -max-turns int
    	agent turn budget (default 30)
  -out string
    	output directory for round artifacts (default ".proofbench/explore")
  -runtime string
    	agent runtime kind (default "claude-code")

Example:
  PB_EXPERIMENTAL=1 pb explore --manifest ready.yaml

Without PB_EXPERIMENTAL=1 set, every pb explore invocation — including pb help explore itself — short-circuits:

$ pb help explore
pb: explore is experimental; set PB_EXPERIMENTAL=1

Exit codes are distinct from the rest of the CLI: 2 when PB_EXPERIMENTAL isn't "1", 3 when the round did not run at all (not-run — e.g. the agent binary is missing), 4 when it ran but produced no proposal (inconclusive). pb explore never returns a verdict and never edits ready.yaml itself — it only ever proposes checks for a human to commit.

report

Renders a Markdown report for a sealed evidence bundle.

$ pb help report
Renders a Markdown report for a sealed evidence bundle.

Example:
  pb report evidence/ENG-123/repro-01

hub

Writes a static HTML index over every evidence bundle under a root directory.

$ pb help hub
Writes a static HTML index over every evidence bundle under a root directory.

Flags:
  -out string
    	output file for the hub index (default ".pb/hub/index.html")
  -root string
    	root directory to scan for bundles (default "evidence")

Example:
  pb hub --root evidence --out .pb/hub/index.html

evidence

Low-level evidence-bundle primitives for building a bundle by hand — pb verify drives these automatically for a full run. pb help evidence <subcommand> prints this same overview for every subcommand; per-subcommand flags are only shown by pb evidence <subcommand> --help (below), which also exits 2 (a flag-parse error) rather than 0.

$ pb help evidence
Low-level evidence-bundle primitives (new, run, add, link, assert, seal, verdict, validate, show) for building a bundle by hand. "pb verify" drives these automatically for a full run.

Example:
  pb evidence new --claim "orders endpoint returns totals" --phase verify

evidence new

Creates a new bundle directory under --root, stamped with claim, phase, ticket, and surface metadata.

$ pb evidence new --help
Usage of pb evidence new:
  -claim string
    	claim under verification (required)
  -kind string
    	bundle kind (e.g. before|after)
  -pairs-with string
    	runId of the paired bundle
  -phase string
    	repro|verify|reverify|fix|report (required)
  -root string
    	root directory for evidence bundles (default "evidence")
  -surface value
    	surface key=value (repeatable, e.g. substrate=local)
  -ticket string
    	ticket key (e.g. ENG-20190)
pb evidence new --claim "orders endpoint returns totals" --phase verify --ticket ENG-123

evidence run

Runs a command, capturing stdout/stderr and exit code as a command artifact in the bundle.

$ pb evidence run --help
Usage of pb evidence run:
  -bundle string
    	bundle directory (required)
  -name string
    	artifact name for the command log (required)
  -shell
    	run the command line via bash -lc
pb evidence run --bundle evidence/ENG-123/verify-01 --name order-roundtrip --shell -- curl -sf http://localhost:8391/orders

Exits with the wrapped command's real exit code — a captured failing command does not itself make pb evidence run fail loudly; the exit code is both returned and recorded in the artifact.

evidence add

Attaches an existing file to the bundle as a typed artifact (screenshot, log, snapshot, recording, or link).

$ pb evidence add --help
Usage of pb evidence add:
  -bundle string
    	bundle directory (required)
  -meta value
    	meta key=value (repeatable)
  -name string
    	artifact name (default: source file basename)
  -type string
    	command|snapshot|screenshot|log|recording|link (default "log")
pb evidence add --bundle evidence/ENG-123/verify-01 --type snapshot orders.json

evidence link

Links an external execution/run URL (e.g. a CI job or dashboard run) to a recorded execution ID.

$ pb evidence link --help
Usage of pb evidence link:
  -bundle string
    	bundle directory (required)
pb evidence link --bundle evidence/ENG-123/verify-01 exec-042 https://ci.example.com/runs/042

evidence assert

Evaluates one expect predicate against the bundle's captured artifacts.

$ pb evidence assert --help
Usage of pb evidence assert:
  -bundle string
    	bundle directory (required)
pb evidence assert --bundle evidence/ENG-123/verify-01 "exitCode(order-roundtrip)==0"

Prints the observed value and exits 1 when the predicate is false, 2 on an evaluation error (e.g. a malformed expression or a missing artifact).

evidence seal

Seals the bundle: computes and writes the manifest's SHA-256 digests, closing it to further artifact writes.

$ pb evidence seal --help
Usage of pb evidence seal:
  -bundle string
    	bundle directory (required)
pb evidence seal --bundle evidence/ENG-123/verify-01

evidence verdict

Sets the bundle's final tri-state verdict, with an optional human-readable note.

$ pb evidence verdict --help
Usage of pb evidence verdict:
  -bundle string
    	bundle directory (required)
  -note string
    	verdict note
pb evidence verdict --bundle evidence/ENG-123/verify-01 --note "set last, from artifacts" pass

evidence validate

Structurally validates a bundle directory (positional BUNDLE_DIR, no flags of its own).

$ pb evidence validate --help
Usage of pb evidence validate:
$ pb evidence validate evidence/ENG-123/verify-01
ok

evidence show

Prints a bundle's manifest as formatted JSON (positional BUNDLE_DIR, no flags of its own).

$ pb evidence show --help
Usage of pb evidence show:
pb evidence show evidence/ENG-123/verify-01
