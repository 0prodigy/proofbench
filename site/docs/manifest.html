ready.yaml

ready.yaml is the per-repo declarative spec of how a service becomes runnable and testable on any substrate. This page is generated from spec/v0/ready.schema.json — every field description below is the schema's own — cross-checked against internal/manifest/types.go (the Go struct shape) and internal/manifest/parse.go (what pb lint actually enforces).

Derive, don't restate — a manifest points into existing truth (compose files, devcontainer.json, Makefile, AGENTS.md) instead of duplicating it.

Top level

FieldTypeRequiredDefaultEffect
servicestringyes—Short identifier for this service (e.g. orders-api). Used as a key in workspace.yaml and as a human-readable label.
rolestringno—One-sentence description of what this service does (e.g. REST API for order lifecycle). Aids auto-generated documentation.
sourcesobject (map<string,string>)no—Map of source-type name to file path for existing project files the harness should read instead of duplicating. Common keys: compose, devcontainer, agentsmd, k8s. The harness derives deps, healthchecks, and env from these files.
runRunSpecyes—Declares the supported run modes and how to start and probe the service.
resourcesobject (map<string,Resource>)no—Map of resource name to Score-style typed dependency. Resources are resolved per substrate via their via map. Use ${resources.<name>.host} placeholders in env overrides.
seedSeedStep[]noemptyOrdered list of seed steps (schema migrations, fixture loading) that prepare the service's data layer. Steps run in order, after their after dependencies are satisfied.
driveobject (map<string,DriveVerb>)noemptyMap of verb name to real product entrypoints the harness may exercise. Drive verbs run actual product paths, not test look-alikes.
checksCheckSpec[]noemptyOrdered list of declared validation surfaces. Each check names the proof-ladder level it proves and the predicates that must hold.
gatesGate[]noemptyHuman gates on destructive or irreversible steps (e.g. cluster deploys, prod writes). A gate blocks the step until approved; an unapproved gate yields inconclusive, never a fake pass.
known_wallsWall[]noemptyKnown failure traps for this service: symptom, root cause, and recovery recipe. Agents and humans consult these before debugging.

Parsing is strict (yaml.v3 with KnownFields(true)): an unrecognized top-level or nested key is a load error, not a silently ignored one.

run (RunSpec)

Supported run modes and the start/probe recipe for each. modes lists the substrates this service can run on; local provides the bare-process recipe; ready is the readiness probe.

FieldTypeRequiredDefaultEffect
modesstring[] (enum)yes, ≥1 item—Substrates this service supports. Values: local (bare process), compose (Docker Compose), k8s-attach (BYOC port-forward), remote (delegate to provider).
localLocalRunrequired when local in modes—Bare-process (local substrate) start recipe.
readyProbenoempty (no probe)Readiness probe using k8s probe vocabulary. The harness polls this until the service reports healthy or the timeout expires.

run.local (LocalRun)

FieldTypeRequiredDefaultEffect
startstringyes when local in modes—Shell command to start the service (e.g. npm run dev, go run ./cmd/server). Runs in the repo root. pb init writes echo TODO: set your start command when it can't derive a real one — pb lint rejects that literal placeholder.
envEnvSpecnoemptyEnvironment configuration for the process.

run.local.env (EnvSpec)

FieldTypeRequiredDefaultEffect
filestringno—Relative path to a .env-style file whose variables are loaded into the process environment (e.g. .env.local).
overridesobject (map<string,string>)noemptyKey-value overrides applied after the file is loaded. Values may reference Score-style resource placeholders (e.g. ${resources.db.host}).
deriveDeriveSpecnounsetDerive environment from a live source (e.g. a running pod) instead of a checked-in file, so config tracks the cluster.

run.local.env.derive (DeriveSpec)

FieldTypeRequiredDefaultEffect
fromstring (enum)yes—Source kind to derive environment from. Only k8s-pod is resolved today (a running pod's environment, read via kubectl exec -- env).
podstringnoservice's own workload (app=<service>)For k8s-pod: the pod name, a deploy/<name> / svc/<name> selector, or an app=<label> selector to read env from.

run.ready (Probe)

Specify exactly one of http, tcp, or exec — pb lint rejects more than one being set.

FieldTypeRequiredDefaultEffect
httpstringnounsetHTTP GET target in :port/path or host:port/path form (e.g. :8080/healthz). The harness polls until it gets a 2xx response.
tcpstringnounsetTCP dial target in :port or host:port form. The harness polls until the connection succeeds.
execstringnounsetShell command whose exit code 0 signals readiness (e.g. pg_isready -h localhost).
timeoutstring (Go duration)no60sMaximum time to wait for readiness in Go duration syntax (e.g. 60s, 2m). The default is applied by the substrate at run time, not by pb lint — lint only checks the value parses.
intervalstring (Go duration)no2sHow often to poll the probe in Go duration syntax (e.g. 2s).

resources (Resource)

A Score-style typed dependency (database, queue, service). The via map resolves the locator per substrate name. Placeholder ${resources.<name>.host} / ${resources.<name>.port} is available in env overrides, probes, drive verbs, and checks.

FieldTypeRequiredDefaultEffect
typestringyes—Semantic resource type (e.g. postgres, kafka, redis, service). The harness uses this to apply substrate-specific defaults.
viaobject (map<string,string>)noemptyMap of substrate name to locator string for this resource on that substrate (e.g. {compose: postgres, k8s: svc/orders-db}).
optionalbooleannofalseIf true, the harness skips this resource when unavailable instead of failing the run.
repostringno—For type service: relative or absolute path to the dependency's repo root, used when the harness needs to bring up the dependency locally.

seed[] (SeedStep)

One seed task (schema migration, fixture load, data initialisation) with an explicit dependency ordering.

FieldTypeRequiredDefaultEffect
namestringyes—Unique name for this seed step within the manifest, used as a dependency reference in other steps' after lists. pb lint rejects a duplicate.
runstringyes—Shell command to execute (e.g. npm run db:migrate). Runs in the repo root.
afterstring[]noemptyNames of seed steps or resource names that must complete successfully before this step runs. Each entry must resolve to a real seed-step or resource name, and steps may not form a cycle — both enforced by pb lint.

drive (DriveVerb)

A real product entrypoint the harness may invoke. Drive verbs exercise actual product paths (not test look-alikes) and may inject identity credentials.

FieldTypeRequiredDefaultEffect
runstringyes—Shell command to invoke the entrypoint (e.g. ./scripts/create-order.sh). Runs in the repo root. Rejected by pb lint if it's still pb init's scaffold placeholder.
identitystringno—Identity injection recipe. env:VAR_NAME reads from an environment variable; other forms TBD.
outputstring (enum: json, text)no—Expected output format of the command for structured parsing.

checks[] (CheckSpec)

A declared validation surface: what to exercise, the proof-ladder level it proves, and the predicates that must hold. Results are captured in the evidence bundle's checks[] array.

FieldTypeRequiredDefaultEffect
namestringyes—Unique name for this check within the manifest. Must match the corresponding Check.name in the evidence bundle; pb lint rejects a duplicate.
levelstring (enum L0–L5)yes—Proof-ladder rung this check proves when it passes. L0=static-valid, L1=builds/loads, L2=unit-green, L3=up+healthy, L4=effect-verified, L5=end-to-end observed.
driverstring (enum: exec, playwright)noexecCheckDriver that exercises this check. Default exec (bash -lc, teed). playwright shells the Playwright CLI and captures trace/screenshots as tool-provenance artifacts.
exercisestringno—What to run for this check: a drive verb reference (e.g. drive.create-order) or a shell command (e.g. playwright tests/e2e/order.spec.ts). Must be non-empty, not scaffolding, and — if of the form drive.<verb> — reference a verb defined in drive.
expectstring[]noemptyList of predicate expressions that must all hold for the check to pass — see the grammar below.
artifactsstring[] (enum)noemptyArtifact types the harness should capture for this check. Values: command, snapshot, screenshot, log, recording, link.
requiresstring[]noemptyEnvironment inputs this check needs (e.g. an operator-supplied execution ID); unset at verify time makes the check record honest not-run with a named reason rather than a hard fail. Each entry must match ^[A-Z_][A-Z0-9_]*$.

expect grammar

Implemented in internal/evidence/assert.go, one predicate per string:

  • exitCode(<artifactName>)==<int> — exit code recorded in a command artifact's meta
  • nonempty(<path>) — file exists and has size > 0
  • rows(<path>)><int> — JSON-array length, else non-empty line count, exceeds int
  • http(<url>)==<int> — GET <url> returns status <int>
  • equal(<pathA>,<pathB>) — two files are byte-identical
  • jsonpath(<artifact>,<path>)==<value> or ~=<regex> — dotted-key path into a captured JSON artifact; bare numeric segments index arrays
  • contains(<artifact>,<path>,<value>) — one-level scan of the resolved array/object for <value>

Examples: exitCode(order-roundtrip)==0, http(http://localhost:8391/healthz)==200, rows(orders.json)>0, jsonpath(execution.json,selectedAction)==quick_run.

gates[] (Gate)

A human gate on a destructive or irreversible step. An ungated destructive step must never execute autonomously.

FieldTypeRequiredDefaultEffect
onstringyes—The trigger event or action that requires human approval (e.g. deploy, drop-table, prod-write, or a drive verb / check name).
reasonstringyes—Human-readable explanation of why this gate exists (e.g. cluster release is irreversible).

known_walls[] (Wall)

A known failure trap: observed symptom, root cause, and recovery recipe. Agents consult known_walls before spending time debugging.

FieldTypeRequiredDefaultEffect
symptomstringyes—Observable symptom string (error message, log line, or behavior) that signals this trap (e.g. 401 from artifact registry).
causestringyes—Root cause of the symptom in plain language (e.g. token expiry).
recoverstringyes—Shell command or step sequence to recover from this trap (e.g. gcloud auth print-access-token | docker login ...).

Validation (pb lint)

pb lint parses strictly (yaml.v3, KnownFields(true) — an unknown field is a load error) and then runs Ready.Validate() (internal/manifest/parse.go):

  • service must be non-empty; run.modes must be non-empty and every value one of local/compose/k8s-attach/remote.
  • Scaffold rejection. pb init writes the literal placeholder echo TODO: set your start command into run.local.start when it can't derive a real one, so it always writes a runnable-looking file. pb lint rejects that exact placeholder wherever it can appear: run.local.start (when local is in modes), any drive[*].run, and any checks[*].exercise — a manifest is not lint-clean until every scaffold command is replaced with the real one.
  • Static probe-URL validation. run.ready allows at most one of http/tcp/exec. An http probe is normalized the same way the local/compose substrates do (:8080/healthz → http://localhost:8080/healthz) and must then url.Parse cleanly. timeout/interval, if set, must be valid Go durations — lint only checks parseability; the 60s/2s defaults are applied by the substrate at run time, not by lint.
  • seed step names must be unique; every after entry must resolve to another seed-step name or a resource name; seed steps may not form a dependency cycle (checked via topological sort).
  • checks names must be unique; level must be L0–L5; driver, if set, must be exec or playwright; exercise must be non-empty and not scaffolding; a drive.<verb> exercise must name a verb that exists in drive.
  • requires name pattern. Every checks[*].requires entry must match ^[A-Z_][A-Z0-9_]*$ — a plausible env-var name, rejecting typos like a lower-case or hyphenated entry before they silently never match anything at verify time.

Example — local substrate

The complete, unmodified examples/basic/ready.yaml (passes pb lint):

service: basic-orders
role: Minimal HTTP order-capture service (Proofbench example)

run:
  modes: [local]
  local:
    start: go run .
  ready:
    http: ":8391/healthz"
    timeout: 30s
    interval: 1s

drive:
  create-order:
    run: "curl -sf -X POST http://localhost:8391/orders -H 'Content-Type: application/json' -d '{\"item\":\"widget\",\"qty\":1}'"
    output: json

checks:
  - name: up
    level: L3
    exercise: "curl -sf http://localhost:8391/healthz"
    expect:
      - "http(http://localhost:8391/healthz)==200"

  - name: order-roundtrip
    level: L4
    exercise: drive.create-order
    expect:
      - "exitCode(order-roundtrip)==0"
      - "rows(orders.json)>0"

Example — k8s-attach substrate

Trimmed from fixtures/k8s-attach/eng-17397-actions-controls.ready.yaml — a full BYOC proof against a live cluster (see Attach your cluster for the full walkthrough):

service: appservice
role: >-
  Lyric note-execution + Actions & Controls (ENG-17397). Proves per-scenario
  action resolution, run-override precedence, ... against a live BYOC appservice.

sources:
  k8s: "svc/appservice:8000"
  repo: /Users/prodigy/lyric/appservice

run:
  modes: [k8s-attach]
  local:
    env:
      derive:
        from: k8s-pod
        pod: "deploy/appservice"
  ready:
    tcp: "${resources.appservice.host}:${resources.appservice.port}"
    timeout: 60s
    interval: 2s

resources:
  appservice:
    type: service
    via:
      k8s: "svc/appservice:8000"
    repo: /Users/prodigy/lyric/appservice
  mongo:
    type: mongodb
    via:
      k8s: "svc/mongodb-svc:27017"
  kafka:
    type: kafka
    via:
      k8s: "svc/kafka-cluster-kafka-brokers:9092"

drive:
  configure-action:
    run: >-
      ~/.claude/skills/lyric-qa/scripts/lyric-mongo.sh --env "$PB_K8S_NAMESPACE"
      --context "$PB_K8S_CONTEXT" --db lyric --eval "..."
    output: json
  fire-execution:
    run: >-
      ~/.claude/skills/lyric-qa/scripts/lyric-fire-execution.sh
      --env "$PB_K8S_NAMESPACE" --context "$PB_K8S_CONTEXT"
      --scenario-id "$PB_SCENARIO_A" --sequence-id "$PB_SEQUENCE_ID"
      --sequence-note-id "$PB_SEQ_NOTE_ID"
    output: json

checks:
  - name: appservice-up
    level: L3
    exercise: >-
      curl -sf -o /dev/null "http://${resources.appservice.host}:${resources.appservice.port}/health"
    expect:
      - "exitCode(appservice-up)==0"

  - name: action-resolution
    level: L4
    exercise: "drive.read-execution"
    expect:
      - "jsonpath(execution.json,selectedAction)==$PB_EXPECTED_ACTION"
    requires: [PB_EXECUTION_ID, PB_EXPECTED_ACTION]

gates:
  - on: fire-execution
    reason: >-
      firing a note execution consumes cluster compute and mutates the
      executions/scenarios collections on a shared BYOC cluster — a human
      confirms the target scenario/sequence IDs before the run.

known_walls:
  - symptom: "execution.selectedAction is null / falls back to defaultAction"
    cause: >-
      selectedNotesActions must be keyed by SEQUENCE-NOTE-ID, not noteId —
      the wrong key is a silent no-op.
    recover: >-
      key configure-action / --selected-notes-actions by the sequenceNote
      _id (PB_SEQ_NOTE_ID), not the noteId.
