CI & GitHub Action

action.yml at the repo root wraps pb verify for CI: it builds pb, runs a verification against your manifest, gates the job on the bundle's own verdict, and uploads the evidence bundle as a workflow artifact on every run — pass or fail.

The action references launchwings/proofbench, which isn't public yet. The workflow below is the real, complete interface — drop it in once the repo is public, or point uses: at a private fork/checkout meanwhile.

Inputs

InputDefaultDescription
manifestready.yamlPath to the manifest, relative to working-directory.
substratelocallocal | compose | k8s-attach — k8s-attach requires cluster credentials on the runner.
working-directory.Directory to run pb in (contains the manifest and the repo under test).
evidence-dir.proofbench/evidenceRoot directory for evidence bundles, relative to working-directory.
allow-inconclusive'false'When 'true', an inconclusive verdict passes the step instead of failing it. An unproven change must not read as green.

Outputs

OutputDescription
verdictThe verify verdict read from the bundle's manifest.json (pass|fail|inconclusive).
bundle-pathPath to the evidence bundle, relative to the repo root.

What the action does

  1. Sets up Go (actions/setup-go@v5, pinned to the action's own go.mod).
  2. Builds pb from source. There's no tagged release yet — once v0 is tagged this step becomes a pinned release-binary download instead of a from-source build.
  3. Runs pb verify with your inputs, captures its output, and parses the bundle: <dir> line pb prints on every path that reaches the verify runner — pass or fail.
  4. Reads verdict out of the bundle's own manifest.json (not pb's raw process exit code) and gates the step on it.
  5. Uploads the evidence bundle as a workflow artifact named proofbench-evidence, if: always() — even a failed or inconclusive run leaves a bundle to inspect.

Exit-code gating

The step's own exit code follows the bundle's verdict, never pb's raw exit status:

case "$verdict" in
  pass)
    exit 0
    ;;
  inconclusive)
    if [ "${{ inputs.allow-inconclusive }}" = "true" ]; then
      exit 0
    fi
    echo "::error::verdict is inconclusive (pb exit $rc); set allow-inconclusive: 'true' to accept"
    exit 1
    ;;
  fail)
    echo "::error::verdict is fail (pb exit $rc)"
    exit 1
    ;;
esac

pass succeeds unconditionally. fail always fails the job. inconclusive fails the job too, unless you opt in with allow-inconclusive: 'true' — a run that didn't reach its declared proof level must not read as green by default. A missing bundle path or an unrecognized verdict string also fails the step, loudly, rather than silently passing.

A complete workflow

name: proofbench
on:
  pull_request:

jobs:
  verify:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: launchwings/proofbench@main
        id: verify
        with:
          manifest: ready.yaml
          substrate: local
          working-directory: .
          evidence-dir: .proofbench/evidence
          allow-inconclusive: 'false'

      - name: Report verdict
        if: always()
        run: |
          echo "verdict: ${{ steps.verify.outputs.verdict }}"
          echo "bundle:  ${{ steps.verify.outputs.bundle-path }}"

@v0 will be the pinned ref once the first tagged release lands; until then, use @main.

Substrate note

Setting substrate: k8s-attach in CI means the runner itself needs a working kubeconfig context and granted namespace access — see attach your cluster for what that substrate does and doesn't do to the cluster.
