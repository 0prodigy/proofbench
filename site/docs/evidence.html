Evidence & provenance

An evidence bundle is the portable, tamper-evident output directory of one verification run: a manifest (manifest.json) plus the captured artifacts it references. The harness collects the evidence — never the agent's narration.

evidence/20260704-101500-verify/
  manifest.json          # schema v2: checks, artifacts, verdict, proof level
  01-up.log              # captured stdout+stderr from the health check drive
  02-order-roundtrip.log # captured stdout+stderr from the order drive verb

Every artifact recorded in manifest.json looks like this — trimmed from the landing page's own pipeline entry:

{
  "type": "command", "name": "03-fire",
  "sha256": "a3f1c2...",
  "provenance": "harness",
  "meta": { "cmd": "./scripts/create-order.sh", "exitCode": 0 }
}

For the exact type and field for every property, see the evidence bundle format reference — generated field-by-field from spec/v0/evidence-v2.schema.json.

Tri-state checks

Every declared check reports one of three states — never a silent default-green:

pass fail not-run

A check that couldn't execute (a gate wasn't approved, a required input was unset) is recorded as not-run with a reason — never omitted, and never a fabricated pass. From the landing page's own trust section, a real shape:

"checks": [
  { "name": "order-roundtrip", "state": "pass",
    "artifacts": ["03-fire", "sn-post"] },
  { "name": "e2e-ui", "state": "not-run",
    "reason": "gate: cluster deploy pending" }
]

Provenance (ADR-0013)

Provenance is a three-value enum on every artifact — the sharp semantics are the product's anti-fabrication claim:

  • harness — strictly harness-spawned and teed: the binary ran the process and captured the bytes itself.
  • tool — harness-directed tool output (Playwright traces, screenshots): the harness chose the tool, its flags, and its output path, but did not tee the bytes.
  • agent — operator/agent-supplied files, including Seal's sweep of untracked files. Only harness provenance can anchor a verdict.

Pairing (before/after)

A bundle may name its role in an explicit before/after pair via kind (before / after) and pairsWith, the runId of its complement. Pairing is always by explicit ID — never inferred from filename or timestamp convention, so a report can't accidentally compare the wrong two runs.

Seal + sha256

At verdict time, Seal recursively scans the bundle directory for any file present on disk but absent from the manifest — including a driver's own subdirectory, like a Playwright trace.zip — and registers each as an artifact (provenance agent) with its path relative to the bundle root. Nothing in the bundle goes untracked. Every non-link artifact carries a hex-encoded SHA-256 digest of its file contents, giving the bundle tamper-evidence: if the file on disk changes after the seal, the digest no longer matches.

Pins

A flat key-value map of exact versions/SHAs for everything exercised in the run — repo commit, image digest, cluster context — so the run can be reproduced or its target unambiguously identified later.

Real example — k8s-attach verify bundle

Trimmed from a real ENG-17397 run against the redcat cluster. Three checks record honest not-run because their requires inputs were unset or their exercise target didn't exist yet — not a fabricated pass:

  "schema": 2,
  "runId": "20260710-010422-verify",
  "claim": "",
  "phase": "verify",
  "surface": {
    "substrate": "k8s-attach"
  },
  "pins": {
    "image.appservice": "us-docker.pkg.dev/development-367210/lyric/appservice@sha256:c2f08138...",
    "k8s.context": "arn:aws:eks:us-east-1:411564643746:cluster/redcat-cluster",
    "k8s.namespace": "redcat",
    "repo": "9e40c8a19e48c8001d8b21f8e044f87bb3a96b1a-dirty"
  },
  "proofLevel": "L3",
  "startedAt": "2026-07-10T01:04:22Z",
  "finishedAt": "2026-07-10T01:05:44Z",
  "checks": [
    {
      "name": "appservice-up",
      "state": "pass",
      "level": "L3",
      "expect": "exitCode(appservice-up)==0",

    {
      "name": "action-resolution",

      "expect": "exitCode(stage-log-observed)==0",
      "reason": "exercise file not found: tests/e2e/eng-17397-stage-log.spec.ts"
    }

  "artifacts": [
    {
      "type": "command",
      "name": "appservice-up",
      "path": "01-appservice-up.log",
      "sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",

        "cmd": "curl -sf -o /dev/null \"http://127.0.0.1:56493/health\"",

    }
  ],
  "verdict": "pass",
  "note": "1 pass, 0 fail, 3 not-run"
}

The verdict here is pass because the only check that ran, passed — but the report still names L3, not "done", and the not-run entries stay in the bundle rather than being dropped, so the next reader sees exactly what was and wasn't proven. See the proof ladder for what each rung requires.
