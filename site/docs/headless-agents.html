Headless agents

experimental

pb explore runs your agents on your own subscription: Proofbench shells out to the customer-installed, genuine claude binary (claude -p --output-format stream-json) rather than linking the Claude Agent SDK, and inherits whatever auth is already installed — a subscription OAuth token, an API key, or Bedrock/Vertex credentials. Auth is entirely Claude Code's own concern; credentials never touch Proofbench (ADR-0014).

pb explore walkthrough

Experimental and gated behind an env var — it exits 2 immediately if unset:

PB_EXPERIMENTAL=1 pb explore --manifest ready.yaml \
  --out .proofbench/explore --runtime claude-code --max-turns 30

--out, --runtime, and --max-turns all have the defaults shown above; only --manifest plus PB_EXPERIMENTAL=1 are required. One round asks the agent to propose new checks for surfaces the manifest's existing checks[], drive verbs, and resources don't already cover — read-only exploration, no file edits, no prose, JSON matching a fixed schema only.

A round writes exactly two files to --out:

  • round.json — always written: status, reason, session ID, cost, turn count, duration, permission denials, runtime version.
  • proposed-checks.json — only when the round's status is proposed: the raw {"checks": [...]} array matching the schema.

pb explore never writes or edits ready.yaml, and it never produces a verdict — a proposal is a suggestion for a human (or a later, separate step) to commit, not a pass/fail claim.

one exploratory round: 9 turns · 8 proposed checks · $1.70 on the operator's own plan

Failure taxonomy

Every failure maps to an honest not-run or inconclusive status — never a false pass/fail. pb explore's own exit code follows the same split: 0 proposed, 2 PB_EXPERIMENTAL unset, 3 not-run, 4 inconclusive.

CategoryTriggersStatus
runtime_unavailablemissing/unexecutable claude binarynot-run
auth_invalidauthentication_failed, oauth_org_not_allowed, expired loginnot-run
rate_limitedrate_limit, overloaded, billing_error — including the 5-hour rolling window and weekly capnot-run
budget_exhaustederror_max_turnsinconclusive
protocol_errornon-zero exit with unparseable stdout, error_during_execution/error_interrupted/error_initialization, or a clean exit that skips structured_outputinconclusive

Binary discovery and version pinning become part of the evidence record (claude --version captured every round). Rate-limit and budget exhaustion are Proofbench's problem to schedule around — the harness backs off and retries the next window rather than marking a proof round failed.

Security invariants

  • Never --bare on the subscription path — bare mode skips OAuth/keychain reads and doesn't read CLAUDE_CODE_OAUTH_TOKEN.
  • Never --dangerously-skip-permissions inside a customer repo.
  • --allowedTools Read,Glob,Grep / --disallowedTools WebFetch,WebSearch on every round — an exploratory round reads the repo, it never fetches the network.
  • A warning (not a refusal) when ANTHROPIC_API_KEY is present alongside a subscription token — in -p mode the API key is always used when present and silently outranks the subscription, risking surprise metered spend.

PB_CLAUDE_BIN

Overrides which claude binary pb explore shells out to — set it to point at a specific install; otherwise Proofbench looks up claude on PATH. A miss (unset override that doesn't resolve, or no claude on PATH) is a not-run with runtime_unavailable, never a failed check.

Agent-neutral by construction

The same shape — discover binary, inherit customer auth, one-shot exec with a prompt, parse a terminal JSON record — fits codex exec --json, gemini -p, and openhands --headless. Adding a second engine is one more shell-out adapter sharing this contract and failure taxonomy, not a redesign.

What counts as proof

Nothing an agent merely observed in an exploratory round counts as proof. The only lasting output is durable automation — committed checks[] entries and Playwright specs — replayed deterministically by the harness thereafter. A proposal earns a rung on the proof ladder only once it lands as a check the harness itself can re-run.
