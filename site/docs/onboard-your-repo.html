Onboard your repo

The quickstart runs a manifest someone already wrote. This walks the other direction: a real service with no ready.yaml yet, brought to a passing L4 verdict. Every command below ran for real, in order, in a scratch directory — paste them in the same order and you get the same shape of result.

The service

A ~35-line toy — noteservice. GET /health for liveness, POST /notes appends the request body to notes.log. No framework, no dependencies:

#!/usr/bin/env python3
# noteservice: GET /health (liveness), POST /notes (appends body to notes.log).
# Start with: python3 app.py   Port: 8931
from http.server import BaseHTTPRequestHandler, HTTPServer

PORT = 8931
NOTES_LOG = "notes.log"


class Handler(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/health":
            self.send_response(200)
            self.end_headers()
            self.wfile.write(b'{"status":"ok"}\n')
        else:
            self.send_response(404)
            self.end_headers()

    def do_POST(self):
        if self.path == "/notes":
            length = int(self.headers.get("Content-Length", 0))
            body = self.rfile.read(length)
            with open(NOTES_LOG, "ab") as f:
                f.write(body + b"\n")
            self.send_response(201)
            self.end_headers()
            self.wfile.write(b'{"status":"created"}\n')
        else:
            self.send_response(404)
            self.end_headers()

    def log_message(self, fmt, *args):
        pass


if __name__ == "__main__":
    print(f"noteservice listening on :{PORT}")
    HTTPServer(("", PORT), Handler).serve_forever()

pb init

Run it from the service's directory, no flags needed:

noteservice
pb init
ready.yaml
next steps:
  1. edit ready.yaml — set start:, ready:, and a checks: block
  2. pb lint # validate the manifest
  3. pb verify # bring up, exercise, produce an evidence bundle

pb init detects project shape from things already in the repo (Docker Compose files, a Procfile, package.json scripts, a Makefile, go.mod) plus a best-effort grep for a health-check path and port. This service has none of those build files, so it writes a draft that's honest about what it couldn't figure out:

service: noteservice
role: 'TODO: describe this service'
run:
    modes:
        - local
    local:
        start: 'echo TODO: set your start command'
    ready:
        http: :8931/health

Note what it got right without being told: the readiness probe (:8931/health, grepped straight from app.py). What it couldn't derive — a start command — it marks with a literal TODO placeholder rather than guessing.

pb lint on the unedited draft

Run pb lint before touching anything:

noteservice
pb lint
pb: manifest.Validate: run.start is generated scaffolding — replace "echo TODO: set your start command" with your real start command

Exit code 1. This is by design, not a bug: pb init always writes a file (so there's something to edit) but pb lint refuses to pass an unedited scaffold — a manifest that would silently "start" a service by echoing a string never actually runs the product. Fixing this one line is the whole job of the next section. Run pb help init or pb help lint anytime for the full flag list.

Edit ready.yaml, field by field

Full field reference: ready.yaml. Here's what each field means as we set it:

  • service — the name recorded in every bundle this manifest produces (surface / bundle identity). pb init already set this from the directory name.
  • role — a one-sentence description; documentation only, replace the TODO.
  • run.local.start — the real command that boots the service as a bare process: python3 app.py.
  • run.ready — the probe pb ready polls until healthy. pb init already found it; add a timeout and poll interval.
  • drive.<verb> — a real product entrypoint the harness may exercise, named so checks[] can reference it as drive.<verb>. Here, the actual POST /notes call — never a test look-alike.
  • checks[] — what gets verified: a proof-ladder level, what to exercise, and expect predicates that must all hold.
service: noteservice
role: Minimal HTTP note-capture service (Proofbench onboarding walkthrough)

run:
  modes: [local]
  local:
    start: python3 app.py
  ready:
    http: ":8931/health"
    timeout: 30s
    interval: 1s

drive:
  create-note:
    run: "curl -sf -X POST http://localhost:8931/notes -H 'Content-Type: application/json' -d '{\"text\":\"first note\"}'"
    output: json

checks:
  - name: up
    level: L3
    exercise: "curl -sf http://localhost:8931/health"
    expect:
      - "http(http://localhost:8931/health)==200"

  - name: note-roundtrip
    level: L4
    exercise: drive.create-note
    expect:
      - "exitCode(note-roundtrip)==0"
      - "rows(notes.log)>0"

Two checks, two rungs: up proves the process is healthy (L3); note-roundtrip proves the drive verb ran and its effect landed — a row in notes.log (L4). See the proof ladder for what each rung means.

When verify fails

With the service stopped (pb down above already did that — the same real failure shows up if you instead point run.ready.http at the wrong port), running pb verify again produces an honest fail, not a hang or a false pass:

noteservice
pb verify --manifest ready.yaml --ticket ONB-001 \
  --claim "notes endpoint appends to notes.log"
bundle: evidence/20260710-053749-verify
proof: none
verdict: fail
note: 0 pass, 2 fail (up, note-roundtrip), 0 not-run
  [fail] up — http(http://localhost:8931/health)==200: Get "http://localhost:8931/health": dial tcp [::…
  [fail] note-roundtrip — expect failed: exitCode(note-roundtrip)==0

Exit code 1. proof: none — no rung was earned, not even L3, because the up check itself failed. Each [fail] line names its own reason after the em dash: a connection refused for up (truncated with an ellipsis when the underlying Go error is long — still legible), and a predicate failure for note-roundtrip once the drive verb couldn't reach a dead service. The bundle is written anyway — a fail is still evidence you can hand to whoever's debugging it.

Recover with pb up --manifest ready.yaml, then pb ready, then re-run pb verify.

Clean up

rm -rf evidence notes.log .pb
