workspace.yaml & environment

Everything below is configuration that lives outside ready.yaml: the org-level workspace.yaml graph, and every environment variable Proofbench itself reads.

workspace.yaml

workspace.yaml is the org-level graph (internal/manifest/types.go's Workspace struct): a directory-scoped file, read from beside the manifest, that names sibling repos and cluster contexts once instead of repeating them in every ready.yaml.

FieldTypeRequiredDefaultEffect
servicesobject (map<string,string>)noemptyService name → repo path. Lets a manifest or driving script resolve a sibling repo by name instead of a hardcoded absolute path.
contextsobject (map<string,string>)noemptyNamed cluster context for the k8s-attach substrate, value in <kube-context>@<namespace> form (or just <namespace>, using the current kubeconfig context). No cluster credentials ever live here — only a context name resolved from the local kubeconfig, plus a namespace (ADR-0008).

Honesty note: unlike ready.yaml, workspace.yaml has no JSON schema yet — manifest.LoadWorkspace parses it strictly (unknown fields rejected) against the Go struct directly, but there is no spec/v0/workspace.schema.json to point pb lint or an IDE at today.

The "context@namespace" convention

Within contexts, the key k8s-attach is special: internal/substrate/k8sattach.go's workspaceContext reads Contexts["k8s-attach"] first. If that key is absent but exactly one context entry exists, that sole entry is used as the default instead (so a single-cluster workspace doesn't need to name the key explicitly). The value is split on the first @: the part before is the kubectl context, the part after is the namespace; with no @, the whole value is treated as a namespace against the current kubeconfig context.

contexts:
  k8s-attach: "redcat@redcat"   # <kube-context>@<namespace>

Full example

From fixtures/k8s-attach/workspace.yaml (real, checked-in fixture):

services:
  appservice: /Users/prodigy/lyric/appservice
  metadata-service: /Users/prodigy/lyric/metadata-service

contexts:
  # <kube-context>@<namespace>. redcat's app namespace; adjust to the granted
  # namespace on your kubeconfig.
  k8s-attach: "redcat@redcat"

Environment variables

Every PB_* variable Proofbench reads (grep -rn "Getenv" internal/ cmd/):

VariableConsumed byEffectDefaultExample
PB_K8S_CONTEXT internal/substrate/k8sattach.go Overrides the kubectl context the k8s-attach substrate targets, taking precedence over any context named in workspace.yaml. the context resolved from workspace.yaml, else kubectl's current-context export PB_K8S_CONTEXT=redcat
PB_K8S_NAMESPACE internal/substrate/k8sattach.go Overrides the granted namespace the k8s-attach substrate port-forwards into, taking precedence over workspace.yaml. Required (from one source or the other) — k8s-attach errors if no namespace resolves at all. the namespace resolved from workspace.yaml export PB_K8S_NAMESPACE=redcat
PB_EXPERIMENTAL cmd/pb/main.go Gates pb explore (the embedded headless-agent runtime). Must be exactly "1"; anything else exits 2 with an explanatory message rather than running. unset (feature off) PB_EXPERIMENTAL=1 pb explore --manifest ready.yaml
PB_RUN_TIMEOUT internal/evidence/run.go Maximum duration for a command captured via pb evidence run / a check's exercise command, in Go duration syntax. Unset means no timeout is applied; a set-but-unparseable value is an error (a typo can't silently disable the timeout). unset (no timeout) export PB_RUN_TIMEOUT=5m
PB_CLAUDE_BIN internal/agentruntime/claudecode.go Overrides which claude executable the headless Claude Code adapter shells out to (resolved via exec.LookPath); used when the genuine binary isn't the one on PATH. claude resolved from PATH export PB_CLAUDE_BIN=/opt/claude-code/bin/claude

Two non-PB_* variables are also read directly by the headless Claude Code adapter (internal/agentruntime/claudecode.go) because it inherits whatever auth the customer's own claude install already has: ANTHROPIC_API_KEY and CLAUDE_CODE_OAUTH_TOKEN. Proofbench never reads their values, only whether both happen to be set at once (surfaced as a preflight warning, since the API key silently outranks the subscription token in -p mode) — see Headless agents for the full auth story and failure taxonomy.

Precedence: env overrides workspace

newK8sAttach (internal/substrate/k8sattach.go) resolves context/namespace in this order, each step able to override the last:

  1. Load workspace.yaml beside the manifest, if present — Contexts["k8s-attach"], else the sole context entry, supplies the default context/namespace.
  2. PB_K8S_CONTEXT, if set, overrides the context.
  3. PB_K8S_NAMESPACE, if set, overrides the namespace.

So workspace.yaml is the checked-in default and the two env vars are the run-time override — the same manifest and workspace file can be pointed at a different cluster for one run without editing anything:

export PB_K8S_CONTEXT=staging
export PB_K8S_NAMESPACE=staging-appservice
pb up --substrate k8s-attach --manifest ready.yaml
