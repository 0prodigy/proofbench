# Honesty spine: the oracle must be signed under an identity the agent cannot assume

The oracle that decides a verdict — the check definitions, the drive bodies and scripts they exercise, and the sha ledger (`manifest.json`) — must be **content-hash-pinned over BEHAVIOR, not labels**, and signed under an **externally-anchored identity the running agent cannot assume**. Anything less is tamper-**evident**, not tamper-**resistant**, and a motivated agent forges a green verdict in one pass. This ADR records the trust-model-**independent** slice that closes two confirmed forgery holes now — complete hashing and honest degradation — and names the anchored-verification slice that comes next.

**Empirical evidence (kill-test E1, 2026-07-10):** the oracle *logic* is compiled into the binary, but the artifacts it judges sit in the agent's write surface. A green verdict was manufactured live by gutting a check's exercise to `exit 0`, weakening a predicate, emptying an `expect:` block into a vacuous pass, self-healing a failing assertion in place, and deleting a check outright. Two deeper holes survived the first hardening pass: (1) **gut-the-drive-body** — leave the check's `exercise` string untouched but rewrite the `drive.<verb>.run` it indirects through, or empty the script that verb runs, so the label is stable while the behavior is hollowed out; and (2) **pin-your-own-key** — the agent generates its *own* ed25519 key, tampers a check, and re-pins with that key, so the lock matches and the signature verifies. A self-held signing key proves internal consistency, which is exactly what E1 forged.

## The decision

- **Complete CheckHash covers BEHAVIOR, not labels (R1).** The per-check content hash folds the fully-resolved `drive[verb]` body (`run` + `identity` + `output`) when the exercise indirects through a verb, the **sha256 of every referenced on-disk script/spec file** the exercise runs, plus `requires`, the matching `gate` (`on` + `reason`), `artifacts`, and `driver`; the set hash additionally covers the set of referenced drive verbs. Pin and verify call the *same* resolution+hash function, so they can never disagree on what "the oracle" is. Gutting a drive body or emptying a referenced script drifts the hash under a fixed label ⇒ the check is `not-run`, never green. A referenced file missing at pin/verify time is an error (not-run), never a silent skip.
- **Local `pb` is SELF-ATTESTED, capped at L3 (honest degradation).** A lock signed by a self-generated/local key proves the check set is internally authentic but says nothing about an external identity the agent could not assume. Such a run — and any run with no valid anchored lock at all — is labeled `SELF-ATTESTED` and its proof ceilinged at **L3**. This closes pin-your-own-key by **truth, not crypto**: the agent may freely mint a key, but a self-minted key can never lift the cap.
- **L4–L5 tamper-resistance requires an externally-anchored identity.** Exceeding L3 requires a lock the runner can chain to **Sigstore keyless** signing (CI OIDC → Fulcio certificate + Rekor transparency log), verified against a **verifier-supplied expected identity** — never the public key the lock itself carries. This shares ADR-0016 R4's trust anchor (a signature is only trusted against a pinned, out-of-band identity, not a self-described one).
- **Self-judged means distinct VERIFIED identities.** The generation-vs-execution split (a check may not be independently attested by whoever ran it) only becomes load-bearing once both identities are *verified* external anchors. Until then there is no verified external signer to compare, so the string-match "signer == executor" heuristic is retired in favor of the self-attested cap.
- **Enforcement auto-caps by ladder and is on by default.** The cap is applied by proof-ladder rung, not by an opt-in flag: any check declared L4/L5 without a valid externally-anchored lock is auto-capped to ≤L3 regardless of any env toggle, and deleting `ready.lock` does not restore legacy-green — absence of a valid anchored lock caps at L3.

## Considered Options

- **Sign the lock with a self-held ed25519 key and trust it (R2/R6 as first drafted).** Rejected: E1's pin-your-own-key forged exactly this — a key the agent holds re-signs after tampering. A self-held signature is authenticity of *content*, not of *signer*; only an externally-anchored identity the agent cannot assume makes a forged green require compromising something the agent does not control.
- **Hash only the check's own labels (name/level/exercise/expect).** Rejected: gut-the-drive-body proved the label is stable while behavior is hollowed out through the `drive.<verb>` indirection and the scripts on disk. The hash must fold the resolved behavior and the referenced bytes, or drift detection is blind to the attack that matters.
- **Gate L4/L5 behind an opt-in "strict" flag.** Rejected: an anti-fabrication product cannot ship a bypass for its own honesty. The cap is by ladder and on by default; `rm ready.lock` degrades to L3, never to green.

## Consequences

- Green above L3 is reachable **only** through the anchored-verify slice below: a run is `SELF-ATTESTED` and capped at L3 unless a lock keyless-signed under CI OIDC verifies against the verifier-supplied expected identity. Local `pb` (self-held key, no `--expected-identity`) stays honestly capped at L3 — the product still does not claim a rung it cannot prove.
- The runner exposes a clearly-marked **anchor seam** (`honesty.AnchorVerifier` / `SetAnchorVerifier`, default self-held-key ⇒ not anchored) that the Sigstore slice implements without touching any caller; the `selfAttested` field is additive on the bundle and spec/v0 schema.
- Complete hashing makes the drive bodies and on-disk scripts first-class oracle inputs: editing a script the harness runs now invalidates the pin, so `pb pin` must be re-run when the exercised behavior legitimately changes.

## Anchored-verify slice (LANDED, 2026-07-10)

The **Sigstore anchored-verify path** is implemented: `honesty.CosignAnchor` (installed via `SetAnchorVerifier`) treats a lock as externally anchored only when its Sigstore keyless signature (`lock.Anchor`, produced by `pb pin` under CI OIDC) verifies via `cosign verify-blob` against a **verifier-supplied** expected Fulcio identity — never one read from the lock. `pb verify --expected-identity <SAN>[-regexp] --oidc-issuer <url>` supplies it; a match clears the self-attested cap and unlocks L4/L5. A genuine-but-non-pinned keyless signature (e.g. a branch run, or an agent's own identity) is confirmed authentic (any-identity `verify-blob`) and stays **self-attested/capped L3**; a forged/tampered bundle fails authenticity and is **refused**.

**PoC evidence (repo `0prodigy/proofbench-ci-trust-poc`, 2026-07-10).** A keyless Fulcio cert's SAN is `https://github.com/<org>/<repo>/.github/workflows/<wf>.yml@refs/heads/main`, issuer `https://token.actions.githubusercontent.com`; a branch/PR run gets `@refs/heads/<branch>`, **un-forgeable by an agent operating in branch context**. `cosign verify-blob --certificate-identity <SAN> --certificate-oidc-issuer <issuer>` ACCEPTS the protected-main signature and REJECTS a branch signature (exit 1). The **operational condition** for the guarantee is branch protection + CODEOWNERS on the signing workflow/`main`, so only a reviewed merge — not a branch push an agent controls — can mint the `@refs/heads/main` identity.

**Shell-out, not embedded (ADR-0012 capability).** `pb` shells out to `cosign` (matching the existing kubectl/playwright pattern) rather than linking `sigstore-go` (+~15MB, a Go bump). cosign absent, an unreachable Rekor tlog, or an identity mismatch degrades **honestly** (not anchored ⇒ self-attested/capped, or refused for an unverifiable keyless lock), never a fake pass. Where the environment MITMs/blocks `rekor.sigstore.dev`, `--insecure-ignore-tlog` (mirrored, off by default) degrades to the offline-verifiable Fulcio-cert identity binding at **reduced assurance**, stamped into the bundle surface. In-process `sigstore-go` remains the upgrade path (`ponytail` note in `honesty/anchor.go`) if the runtime dependency ever becomes unacceptable.
