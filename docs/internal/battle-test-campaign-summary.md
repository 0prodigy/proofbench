# Battle-test campaign — 12 blind Sonnet battle-tests (summary)

*12 real merged PRs across a wide range (2 very-big: PostHog, Sentry), analyzed blind by Sonnet (the production driver). Blind verdicts: {"WORKS": 4, "COULD_NOT_DETERMINE": 7, "DOES_NOT_WORK": 1}. No false-WORKS across 12. Full per-PR results in the workflow journal.*

# Battle-test campaign — does the theory survive at scale, driven by Sonnet?

## 1. Verdict on the theory

**The honesty core survives, but the current mechanization (1.1–1.5 + FW-1/2/3/11/12/14) is not yet complete enough to build the E1 gate without one more hardening pass.**

Evidence: across 12 PRs (2 very-big: PostHog #65748, Sentry #106833), the verdict distribution was **7 COULD_NOT_DETERMINE, 4 WORKS, 1 DOES_NOT_WORK** — a strongly conservative distribution, not an agent rubber-stamping plausible-looking diffs. Every single WORKS verdict shipped with an explicit "I did not execute a harness" confession and named its unverified assumptions; every case where the mechanism was genuinely shaky (medusa's dual-leg gap, rudder-server's no-read-surface, PostHog's cross-repo/async holes, Novu's unconstructable precondition) was correctly routed to CND rather than rounded up. The core principle — *agent unreliability can cost a WORKS but must never manufacture a false WORKS* — held in aggregate, 12/12.

But this campaign tested a narrower thing than "does the mechanized pipeline produce correct verdicts": it tested "does Sonnet, reasoning under the theory's rules with no executed harness, correctly discipline its own claim-compiling and verdict-predicting." That discipline held only because Sonnet did a lot of *unmechanized* extra work per PR (off-repo dependency hunts, oracle-provenance skepticism, diff-archaeology to find the real discriminating claim). The 12 reports independently surfaced ~20 concrete gaps in the current mechanization — several of which (vacuous negative effect-checks, owner-shadow via session/auth conflation, naive store-diffing) are exactly the cheap tricks a hostile or careless driver would find first in production. None of these breaks the philosophy (propose/dispose, CND-by-default, dual-leg, quantifier lint); all are closable with named sub-mechanisms. That is the difference between "the theory is sound" (yes) and "the theory is ready to gate" (not quite).

## 2. The Sonnet question (critical)

**Every one of the 12 `sonnetDifficulty` fields independently confesses the same failure shape**: the mechanical checklist (1.1–1.5) was never what was hard. What was hard, every time, was a *discovery* step outside the checklist:

- **Finding state/behavior that lives outside the diff.** AppFlowy's real persistence primitive is in a third-party `collab-folder` crate never touched by the diff; PostHog's rerun-paging logic lives in a capability-gated worker not visible in default compose; Sentry's actual assertion evaluation lives in a wholly separate Rust repo reached only via Kafka; medusa's real discriminating power depends on a fulfillment-provider plugin never mentioned in the diff. In each case, a diff-only read (which is what "blind" nudges toward) misses the load-bearing fact, and the report says so explicitly ("a less careful pass would have...").
- **Distinguishing a privileged, PR-authored test oracle from a genuine front-door read.** rudder-server hands you a working `COUNT(*)`-based integration test that *looks* like a legitimate effect check; recognizing it as a white-box shortcut a hostile-user-shaped driver could never reach took deliberate resistance, not a rule lookup.
- **Resisting "the code looks right, mechanism is deterministic, ship WORKS."** Named explicitly in AppFlowy, Documenso, and n8n as the single strongest pull — and the reports say a lower-effort pass would have taken it.
- **Picking the ONE non-vacuous discriminating claim among several candidates.** cal.com, Ghost, and medusa all had multiple plausible claims where the "loudest verb" was the wrong (already-true, or narrower) one; finding the real one took cross-file diff-archaeology.
- **Vocabulary judgment calls with no mechanical answer.** twenty's webhook endpoint made "navigate" and "forge" byte-identical; Novu's precondition is API-only with no UI path at all; AppFlowy/supabase needed drag/scroll primitives the vocabulary never names. Each required a from-scratch policy call, not a lookup.

**Conclusion: the theory is not philosophically genius-dependent, but its current *procedure* is.** The safety net (CND-by-default, NOT-EXECUTED→CND, dual-leg) means that when Sonnet's judgment falls short, the failure mode observed here is "defaults to caution" (safe direction) — not silent false-WORKS. That is a real point in the theory's favor. But that safety net only fired because Sonnet, unprompted, went looking for the discovery-step gaps in the first place. A production driver under time/tool-budget pressure (explicitly named as a risk in the PostHog and Sentry reports) will skip those extra searches, and the checklist alone will not catch what it skips — it will silently under-deliver EXECUTED effect checks or, worse in a few cases (Cluster A/B/D below), silently accept a check that shouldn't count.

**What must become mechanized (not left to judgment) to make this Sonnet-executable at production tool budgets:**
1. A **mandatory off-diff dependency scan** before any claim is compiled: grep the target repo *and* declared cross-repo devservices for the actual persistence/execution primitive, never trust the diff's file list as complete scope.
2. A **mandatory oracle-provenance check**: any effect-check source that is code shipped *by the PR under test* (its own test helpers, its own privileged query) is disqualified as a front-door oracle by rule, not by vigilance.
3. An explicit **vocabulary decision table** per interaction class (drag, native scroll/observer-triggered, canvas hit-testing, documented API/SDK calls, bare-URL ingress) so the "is this a walk or a forge" call is a lookup, not a fresh judgment each time.
4. A **claim-enumeration step**: list every behavioral axis the diff touches and screen each independently for vacuousness before picking the compiled promise, rather than compiling the loudest verb.

## 4. Where the theory works well vs poorly, by size & type

- **Native client (AppFlowy, small drag feature buried in a medium PR):** CONJURE topology holds cleanly (repo already ships a from-source integration harness with cold-boot-per-test). Breaks on vocabulary (drag isn't in click/type/navigate/read) and on the oracle (1.1's "diff the store" has no answer for a CRDT document owned by a dependency crate). Mutation-attribution calibration (1.2) is validated hard here — a single drag fires 2N toggle round-trips that must fold into one attributed effect.
- **Backend-only data pipeline (rudder-server, medium):** CONJURE topology is genuinely real (the PR's own integration test proves it). The theory still correctly forces CND on the core claim — not because the environment is weak, but because the feature has *no user-facing read surface at all* and its only egress leg targets an ambiguous operator-level sink. This is the clearest proof that a perfect CONJURE environment does not guarantee a resolvable verdict; some features are structurally CND by their own shape.
- **Very-big (PostHog #65748, Sentry #106833):** Both correctly resisted false WORKS at scale — the theory does *not* degrade into "trust it because the diff is huge and careful." But size multiplies discovery burden: more off-repo consumers, more feature flags, more cross-repo services, more versioned-store idiosyncrasies, each an independent place a lazier pass would silently miss something. Both very-big cases needed genuinely non-mechanical archaeology (PR-timeline reconstruction for Sentry, source-registry search for PostHog) that a diff-only read would not have surfaced.
- **Egress-heavy (Novu, small):** The WALK-vs-CND carve-out mechanism works technically (HMAC content-binding to a controlled receiver is a clean substitute for the fresh-session leg). It broke on two things orthogonal to egress mechanics: the precondition itself is unconstructable through a strict UI-only front door (API-only credential), and the destination-override field isn't bound to the configured credential (SSRF-shaped). Egress-heavy features expose the vocabulary and credential-binding gaps faster than persisted-state features do.
- **Small (Documenso, novu):** Size does not correlate with ease. Documenso's clean, small diff still forced a hard concurrency-reasoning judgment call (Konva event-bubbling vs React batching) to determine whether the PR is a genuine fix or a no-op, and its own report is the one that surfaced the meta-gap about receipts-vs-prose. What predicts difficulty is *store shape, front-door reachability, and single-leg-observability* — not line count.
- **The one DOES_NOT_WORK case (supabase, medium):** Proves the theory has genuine discriminating power in blind-prediction mode, not just a tendency to hedge to CND — the offset-pagination insert-shift bug was derived by hand-tracing the algorithm, not guessed. This is a good sign: the theory doesn't just protect against false-WORKS, it can also correctly predict a real DOES_NOT_WORK from first principles.

## 6. Required revisions (ranked) + what stays genuinely open

**Mandatory — must be folded into the day-one mechanism spec before an E1 malicious-driver gate is meaningful** (these are exactly the cheap tricks a hostile driver would try first):

1. **Attempted-action receipt for negative/blocking claims** (Cluster #1 above). *Resolved by spec, needs implementation.*
2. **Auth-context receipt + non-quantified owner-shadow guard** (#2). *Resolved by spec, needs implementation.*
3. **Oracle-provenance disqualification of PR-authored test/verification code as an effect-check source.** *Resolved by spec, needs implementation.*
4. **Per-storage-engine diff adapters for mechanism 1.1** (#3). *Resolved by spec (adapter classification step), needs per-engine implementations (relational done; CRDT, MergeTree-variant, sparse-wide-column still to build).*
5. **Vocabulary extension with explicit per-class authenticity rules** (#4), including explicit flagging (not silent resolution) of navigate≡forge cases. *Resolved by spec, needs implementation + a documented decision table.*
6. **Mandatory off-diff dependency scan** before claim compilation. *Resolved by spec, needs implementation as a pipeline step (not left to agent initiative).*

**Hardening — bound by disclosure or a narrow rule addition, not a new mechanism; can ship alongside E1 with explicit CND-by-rule tags:**

7. Structural-no-front-door-read auto-detected disclosure category (#5). *Bounded.*
8. Egress destination third category (operator-level singleton sink) — CND-by-default unless proven otherwise (#6a). *Bounded.*
9. Egress credential-binding fix for sealed-room allowlisting (#6b). *Resolved by spec, small implementation.*
10. FW-14 split into precondition-async / two-phase-verdict / cross-cycle sub-cases + execution-status-event clock signal (#7). *Resolved by spec, needs implementation.*
11. Known-stub-component registry for non-discriminating pluggable dependencies (#8). *Bounded, needs a maintained list.*
12. Twin-implementation coverage rule (#9). *Resolved by spec, needs a diff-analysis check.*
13. Synthetic-write construction rule for read/projection-only features (#10). *Resolved by spec, needs implementation.*
14. Capability-gated topology discovery + cross-repo SHA pinning in CONJURE (#11). *Engineering backlog item, no conceptual gap.*
15. `CND(no-front-door-yet)` sub-tag for UI-pending backend slices (#12). *Bounded, small implementation.*
16. FW-11 wording generalization to non-actor quantifiers (#13). *One-line spec fix.*
17. Receipts-pointer requirement on the verdict artifact itself (#14). *Bounded, small implementation.*
18. Distinguish harness-bug from code-bug in CND reporting (#15). *Reporting-quality fix, no correctness impact.*

**Genuinely open — name and bound by disclosure only, no clean mechanical fix exists yet:**

- **O1.** UI-pending backend slice in incrementally-delivered codebases — no way to avoid a temporal false-CND without walking past the exact-fingerprint boundary the theory otherwise insists on.
- **O2.** Cross-repo/capability-gated topology discovery will always have a long engineering tail; CONJURE cannot be proven complete, only progressively hardened.
- **O3.** The precise boundary between "native front-door interaction" and "stub-adjacent programmatic shortcut" for canvas/observer-triggered UIs is a judgment call the theory doesn't resolve crisply — different reasonable policies trade off false-CND vs false-WORKS differently.
- **O4.** Whether documented API/SDK calls count as "front door" for API-first products is a product-category policy decision, not a mechanical fact; the theory needs to make an explicit choice and accept the tradeoff (false-CND on strict reading, weaker anti-forging guarantee on loose reading).

## 7. Readiness call

**Not ready to build the E1 malicious-driver gate as currently specified — but the gap is bounded, concrete, and fixable in one revision pass, not a rethink.**

The philosophy is validated: propose/dispose, CND-by-default, dual-leg, and the quantifier lint all did real work across genuinely different stacks (Rust/Flutter, Go/ClickHouse, TypeScript/CRDT, Ruby-adjacent commerce, Python/Kafka) and at both small and very-big scale, and in every case where Sonnet's own judgment was insufficient, the theory's structure pushed the outcome toward caution rather than a false pass. That is the property that matters most and it held 12/12.

But six of the found gaps (Mandatory items 1–6) are precisely the vectors a hostile driver in the E1 gate would probe first — vacuous negative claims and session/auth-context conflation are the cheapest, most mechanical tricks to game, and they are currently unguarded by anything except an agent's own diligence. Shipping E1 before closing them means the gate's headline guarantee ("a WORKS verdict cannot be faked") is untested against exactly the attack surface it exists to close.

**Recommendation:** fold the six Mandatory items into the day-one mechanism spec, then run a second, narrower battle test — 3–5 PRs, adversarially chosen to hit M1–M3 specifically, with an *actually executed* harness this time (every one of these 12 verdicts was a blind prediction, never an executed run) — before green-lighting E1. The Hardening list can land incrementally alongside or after E1 without blocking it, since each degrades gracefully to a disclosed CND rather than a false WORKS.
